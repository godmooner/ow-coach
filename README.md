# OW Coach

내 역할군(탱커·딜러·힐러)과 모스트, 상대 탱커 1명·딜러 2명·힐러 2명, 선택 사항인 전장을 고르면 모스트 1~3순위 안에서 점수순으로 추천하는 v1.0.1입니다. 모스트가 모두 ‘약간 유리’ 이하이면 ‘가능’에서 최고 점수 영웅 한 명을 별도로 보여줍니다. 영웅 53명의 초상화와 전장 30개의 썸네일을 포함합니다.

## 바로 사용하기

[OW Coach](https://godmooner.github.io/ow-coach/)를 브라우저에서 엽니다. 공개 사이트의 반영 버전은 `STATE.md`를 참고하세요. 단일 파일 `OW_Coach.html`을 생성한 경우에는 Chrome 또는 Edge에서 열어 오프라인으로 사용할 수도 있습니다.

1. 탱커·딜러·힐러 중 내 역할군을 고릅니다.
2. 모스트 화면에서 다룰 줄 아는 영웅을 초상화로 고릅니다. 1·2·3순위에는 서로 다른 영웅 한 명씩 지정할 수 있고, 고르면 다음 빈 순위로 자동 이동합니다. 1~2명만 선택하거나 비워 둔 순위가 있어도 **완료**할 수 있습니다.
3. **가능**에는 그 외 다룰 줄 아는 영웅을 원하는 만큼 추가하거나 비워 둡니다. 1~3순위 카드에는 선택한 영웅의 초상화와 이름을, 가능 카드에는 이름만 표시합니다. **전체 선택**은 1~3순위를 유지하고 남은 영웅을 모두 가능에 넣습니다. **전체 해제**는 현재 역할의 모스트만 비웁니다.
4. 순위를 수정하려면 해당 순위 버튼을 누른 뒤 초상화를 누릅니다. 다른 순위의 영웅은 현재 순위로 이동하고, 같은 순위의 영웅은 해제됩니다. **완료**로 진행하거나 **선택 없이 건너뛰기**로 현재 역할의 모스트를 비울 수 있습니다. 추천을 받으려면 1~3순위 중 적어도 한 명을 지정해야 합니다.
5. 상대 선택 화면의 역할 표시 아래에서 모스트 이름을 확인합니다. **모스트 수정**으로 돌아가도 상대 선택은 유지됩니다.
6. 상대 초상화 5명을 고르면 결과가 자동으로 나타납니다. 다시 누르거나 위쪽 선택 슬롯을 누르면 해제됩니다.
7. 상대 목록 아래의 **전장 선택**에서 모드 → 전장 썸네일 순서로 고르면 맵 점수가 반영됩니다. 전장을 고르지 않아도 추천됩니다. 다른 모드의 목록을 열어도 이미 선택한 전장은 유지되며 **전장 해제**로 별도로 지웁니다.
8. 가중치를 시험하려면 화면 위의 **개발용 설정**을 펼칩니다. 슬라이더를 움직이면 바로 다시 계산되고, **기본값으로**를 누르면 기본 가중치로 돌아갑니다. 기본값과 다르면 패널이 접혀 있어도 **변경됨** 표시가 남습니다.

역할을 바꾸면 그 역할의 모스트 화면으로 이동합니다. 선호 영웅과 지정한 순위, 개발용 가중치는 브라우저에 저장해 재방문할 때 복원합니다. 상대와 전장 선택은 현재 페이지에서만 유지합니다. 상대 화면의 **초기화**는 상대 영웅만 비우며, 전장·모스트·가중치는 유지합니다.

주 추천은 **명시적으로 지정한 모스트 1~3순위만** 점수순으로 보여주며, 영웅 이름 옆에 개인 모스트 순위를 표시합니다. 1~2명만 지정하면 그 인원만 추천합니다. 모스트가 없으면 선택 안내가 나오며, 전체 선택으로 가능 영웅만 채워도 주 추천이 생기지 않습니다. 모스트 순위에 따른 가산점·동점 우선권은 없습니다.

주 추천 영웅이 모두 고정 등급 **‘약간 유리’ 이하**이면 가능 중 최고 점수 영웅 **한 명**을 별도 영역에 표시합니다. 모스트 한 명이라도 ‘유리’ 이상이면 추가 추천은 숨깁니다. 가능 영웅이 없으면 추가 카드도 없습니다. 가능 중 최고 점수가 모스트보다 낮거나 불리한 등급이어도 실제 등급·점수를 그대로 보여줍니다. 동점이면 기존 영웅 목록 순서를 따릅니다. 맵·가중치가 바뀌면 이 조건도 즉시 다시 판단합니다.

## 개발 실행

Node.js 24와 npm을 설치한 환경에서 프로젝트 폴더를 열고 실행합니다.

```sh
npm ci
npm run dev
```

터미널에 표시된 주소를 브라우저로 엽니다. 다음 AI는 이 파일과 `STATE.md`, 수정할 실제 파일부터 읽으면 됩니다.

간단한 점수 수정은 `data/build/matchups.json`에서 합니다. 구조는 `{영웅id: {상대id: 점수}}`입니다. **0.4에서 JSON만 53명·2,754개 관계로 교체했습니다. 기존 CSV·XLSX·원문/파서는 0.3 자료이므로, 새 데이터와 동기화하기 전에는 아래 변환 및 원문 재생성을 실행하지 마세요.** 동기화된 CSV를 편집한 경우 다음 명령으로 JSON에 적용할 수 있습니다.

```sh
npm run data:from-csv
```

JSON 직접 편집과 CSV 편집을 동시에 진행하지 마세요. CSV 변환은 JSON을 다시 만듭니다. XLSX는 참고 자료이며, XLSX만 고치면 앱에는 반영되지 않습니다. 표로 편집하려면 CSV의 `score`를 수정한 뒤 위 명령을 사용합니다.

원문에서 다시 생성할 때는 `python3 scripts/parse_matchup.py data/raw`를 실행합니다. 원문 재생성은 수동으로 수정한 점수를 덮어씁니다. 기존 원문과 파서는 보존했습니다.

## 계산 규칙

매우 유리 +3 / 유리 +2 / 약간 유리 +1 / 중립 0 / 약간 불리 −1 / 불리 −2 / 매우 불리 −3. `유동적`은 0점이며 조건부 평균으로 만들어진 소수 점수를 그대로 사용합니다. 점수는 후보 영웅이 상대를 만났을 때 기준입니다.

원문에 없는 관계와 같은 영웅 관계는 계산할 때 0점입니다. 누락 때문에 후보를 제외하지 않습니다. 동점은 같은 순위로 표시하고 `heroes.json`의 순서로 나열합니다. 기본값에서 상대 탱커 항은 내가 탱커일 때 3배, 딜러·힐러일 때 2배입니다. 상대 딜러·힐러 항은 모두 1배입니다.

총점은 다음과 같이 계산합니다.

```text
총점 = 상성 가중치 × Σ(상대 5명 상성 × 상대 역할 가중치)
     + 궁합 가중치 × 아군 궁합 합계
     + 맵 가중치   × 해당 영웅의 전장 점수
```

`BLOCK_WEIGHT` 기본값은 상성 1.0, 궁합 0.0, 맵 0.3입니다. 궁합은 데이터가 없어 합계도 0이며 설정은 비활성입니다. 전장 미선택·맵 관계 누락도 맵 항을 0으로 계산합니다. 예를 들어 상성 합계 5점인 위도우메이커는 하바나(+3)에서 `5 + 0.3×3 = 5.9점`입니다.

첨부 맵 점수는 픽률에서 영웅별 기본 인기도와 전장 전체의 효과를 제거한 값을 −3~+3으로 변환한 자료입니다. 앱에서는 제공된 값을 그대로 읽습니다. 맵 점수는 승률을 뜻하지 않습니다.

등급은 `grade_cuts.json`의 역할별 고정 경계선을 읽어 만듭니다. 총점이 `cuts[i]` 이하이면 `labels[i]`, 모든 경계선을 초과하면 마지막 라벨입니다. 등급을 크게, 원래 점수를 작게 함께 표시합니다. 추천 조합 안에서의 순위·백분위는 등급에 영향을 주지 않으므로, 1위 영웅도 불리한 등급일 수 있습니다. 가중치를 조절해도 경계선은 고정이며, 튜닝 완료 후 별도로 재산출해야 합니다. 파일의 `block_weight`·`enemy_weight`는 코드의 **기본값**과 일치하는지 테스트합니다.

슬라이더 범위는 상성·맵 0~2(0.05 단위), 역할별 상대 탱커 가중치 0~5(0.5 단위)입니다. 선택한 맵과 가중치는 합산 전에 적용하며, 총점은 화면 표시용 두 자리로 반올림해서 정렬하지 않습니다. 소수 곱셈의 미세한 계산 오차만 12자리에서 정리해 수학적으로 같은 점수를 동점으로 유지합니다.

영웅 ID는 내부 식별자이므로 공식 URL과 같을 필요가 없습니다. `freya` → 공식 `freja`, `sion` → 공식 `shion` 등은 초상화 다운로드 단계에서 대응합니다. 기존 JSON·CSV 연결은 유지했습니다.

## 확인과 배포 파일 생성

```sh
npm test
npm run build
npm run portable
```

`dist/`에는 웹 배포용 파일이, `release/OW_Coach.html`에는 초상화와 전장 썸네일을 내장한 더블클릭 실행용 단일 파일이 생성됩니다. 점수나 코드를 바꾸면 다시 생성해야 합니다. 테스트는 맵 미선택·기본 가중치의 v0.5 회귀, 맵 합산·가중치, 데이터 53×30의 완전성, 설정 저장·복원, 고정 등급 경계, 모스트 전용 추천, 가능 추가 추천 조건·경계·빈 선택을 확인합니다. 실제 데이터를 갱신할 때에는 `STATE.md`의 회귀 기준도 함께 검토하세요.

## 나중에 맵 점수를 갱신할 때

1. 새 `map_scores.json`을 `data/build/map_scores.json`에 덮어씁니다. 구조는 `{영웅id: {전장id: 점수}}`이며 소수를 허용합니다. 같은 ID를 유지하면 화면 코드를 고칠 필요가 없습니다.
2. 새 점수 분포에 맞게 등급을 다시 산출했다면 `data/build/grade_cuts.json`도 교체합니다. 가중치를 정식 기본값으로 바꿀 때에는 코드의 기본 상수와 경계선 파일의 기준 가중치를 함께 맞춥니다.
3. `npm test`와 `npm run build`를 실행합니다. 점수 변경으로 실제 데이터 손계산 예제가 달라졌다면 원본 값을 다시 계산해 기대값을 검토합니다. 맵 미선택 v0.5 기준 자료는 맵 점수 변경 때문에 바꾸지 않습니다.
4. 오프라인 파일도 쓰려면 `npm run portable`로 다시 만듭니다. 전장 ID나 목록이 바뀐 경우에만 `maps.json`과 같은 이름의 썸네일까지 함께 갱신합니다.

이미 저장된 사용자 가중치는 데이터 교체로 초기화되지 않습니다. 새 기본 데이터 확인 시 **개발용 설정 → 기본값으로**를 눌러 비교하세요.

## GitHub Pages

1. 프로젝트 내용을 GitHub 저장소의 `main` 브랜치에 올립니다. `node_modules`, `dist`, `release`는 제외합니다.
2. Settings → Pages → Source에서 GitHub Actions를 선택합니다.
3. 이후 `main`에 변경을 올리면 포함된 `.github/workflows/deploy.yml`이 검사·빌드·배포합니다.

v0.5는 [PR #2](https://github.com/godmooner/ow-coach/pull/2)로 병합되었고, v1.0도 `main`의 `0869b1d`에 반영되었습니다. 이번 v1.0.1 패치의 검증·반영 상태는 `STATE.md`를 참고하세요. 파일 경로는 저장소 하위 경로에도 맞게 상대 경로로 처리합니다. [Vite 배포 안내](https://vite.dev/guide/static-deploy#github-pages)

상성 데이터는 제공된 나무위키 추출 자료이며, 초상화는 [오버워치 공식 영웅 페이지](https://overwatch.blizzard.com/en-us/heroes/)에서 확보했습니다. 비공식 팬 도구이며 영웅 이미지 권리는 Blizzard Entertainment에 있습니다.
