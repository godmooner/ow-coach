# OW Coach

내 역할군(탱커·딜러·힐러)과 상대 탱커 1명·딜러 2명·힐러 2명, 선택 사항인 전장을 고르면 점수가 높은 영웅부터 최대 3명을 추천하는 v1.5입니다. 선호 영웅 설정은 선택 사항이며, 영웅 53명의 초상화와 전장 30개의 썸네일을 포함합니다.

## 바로 사용하기

[OW Coach](https://godmooner.github.io/ow-coach/)를 브라우저에서 엽니다. 공개 사이트의 반영 버전은 `STATE.md`를 참고하세요. 단일 파일 `OW_Coach.html`을 생성한 경우에는 Chrome 또는 Edge에서 열어 오프라인으로 사용할 수도 있습니다.

1. 첫 화면에서 탱커·딜러·힐러 중 내 역할군을 고르면 곧바로 상대·전장 선택 화면으로 이동합니다.
2. 상대 초상화 5명을 고르면 결과가 자동으로 나타납니다. 선호 설정이 없으면 해당 역할의 전체 영웅 중 상위 3명을 추천합니다. 다시 누르거나 위쪽 선택 슬롯을 누르면 해제됩니다.
3. 상대 목록 아래의 **전장 선택**에서 모드 → 전장 썸네일 순서로 고르면 맵 점수가 반영됩니다. 전장을 고르지 않아도 추천됩니다. 다른 모드의 목록을 열어도 이미 선택한 전장은 유지되며 **전장 해제**로 별도로 지웁니다.
4. 다룰 줄 아는 영웅만 추천받고 싶으면 역할 표시 아래의 **선호 영웅(모스트) 선택**을 누릅니다. 별도 화면에서 탱커·딜러·힐러 탭으로 역할별 선호를 저장할 수 있습니다.
5. 1·2·3순위에는 서로 다른 영웅 한 명씩 지정할 수 있고, 고르면 다음 빈 순위로 자동 이동합니다. **가능**에는 그 외 다룰 줄 아는 영웅을 원하는 만큼 추가합니다. 1~3순위 카드에는 초상화와 이름을, 가능 카드에는 이름만 표시합니다. 순위 버튼을 누른 뒤 초상화를 누르면 지정·이동·해제할 수 있습니다.
6. **전체 선택**은 1~3순위를 유지하고 남은 영웅을 모두 가능에 넣습니다. **전체 해제**는 설정 중인 역할의 선호만 비웁니다. 비워 둔 순위가 있어도 **완료**할 수 있고, 가능만 선택해도 추천됩니다.
7. **완료**를 누르면 원래 역할의 상대·전장 화면으로 돌아가며 변경한 선호가 반영됩니다. 상대 조합과 전장은 유지됩니다. **선호 해제하고 돌아가기**는 설정 중인 역할의 선호만 지운 뒤 돌아갑니다.
8. 가중치를 시험하려면 화면 위의 **개발용 설정**을 펼칩니다. 슬라이더를 움직이면 바로 다시 계산되고, **기본값으로**를 누르면 기본 가중치로 돌아갑니다. 기본값과 다르면 패널이 접혀 있어도 **변경됨** 표시가 남습니다.

역할을 바꾸어도 모스트 선택을 강제하지 않습니다. 선호 영웅과 지정한 순위, 개발용 가중치는 브라우저에 저장해 재방문할 때 복원합니다. 상대와 전장 선택은 현재 페이지에서만 유지합니다. 상대 화면의 **초기화**는 상대 영웅만 비우며, 전장·선호·가중치는 유지합니다.

주 추천은 **모스트 1~3순위와 가능을 합친 후보** 중 점수순으로 최대 3명을 보여줍니다. 선택한 후보가 총 1~2명이면 그 인원만 표시하며 다른 영웅으로 채우지 않습니다. 이름 옆에는 개인 모스트 순위 또는 가능 표시가 붙습니다. 아무도 선택하지 않았거나 선호를 모두 해제하면 해당 역할 전체가 후보가 됩니다. 모스트 순위에 따른 가산점·동점 우선권은 없습니다.

선호 설정이 있고 주 추천이 모두 고정 등급 **‘약간 불리’ 이하**이면, 같은 역할 **전체 영웅 중 최고 점수 영웅 한 명**을 ‘새로운 영웅 제안’으로 표시합니다. 가능 영웅을 포함해 한 명이라도 중립 이상이면 추가 제안은 숨깁니다. 전체 최고가 주 추천에 이미 있으면 중복 표시하지 않습니다. 추가 영웅 역시 불리할 수 있으므로 실제 등급·점수를 그대로 보여줍니다. 동점이면 기존 영웅 목록 순서를 따르며, 맵·가중치가 바뀌면 조건도 즉시 다시 판단합니다.

## 개발 실행

Node.js 24와 npm을 설치한 환경에서 프로젝트 폴더를 열고 실행합니다.

```sh
npm ci
npm run dev
```

터미널에 표시된 주소를 브라우저로 엽니다. 다음 AI는 이 파일과 `STATE.md`, 수정할 실제 파일부터 읽으면 됩니다.

```sh
npm run data:from-csv
npm run grades:calibrate
```

JSON 직접 편집과 CSV 편집을 동시에 진행하지 마세요. CSV 변환은 JSON을 다시 만듭니다. 누락된 기존 관계·잘못된 수치·중복 관계는 덮어쓰기 전에 거부합니다. Excel은 검토/편집 자료이며 Excel만 바꾸면 앱에 자동 반영되지 않습니다. 기존 `data/raw`·`parse_matchup.py`는 0.3 역사 자료이므로 v1.5 데이터 재생성에 사용하지 않습니다.

## 계산 규칙

매우 유리 +3 / 유리 +2 / 약간 유리 +1 / 중립 0 / 약간 불리 −1 / 불리 −2 / 매우 불리 −3. `유동적`은 0점이며 소수 점수를 허용합니다. v1.5에서는 대인전·팀전 평가가 구분된 18개 관계에 팀전 값을 적용했습니다. 점수는 후보 영웅이 상대를 만났을 때 기준입니다.

원문에 없는 관계와 같은 영웅 관계는 계산할 때 0점입니다. 누락 때문에 후보를 제외하지 않습니다. 동점은 같은 순위로 표시하고 `heroes.json`의 순서로 나열합니다. 기본값에서 상대 탱커 항은 내가 탱커일 때 2배, 딜러·힐러일 때 1.5배입니다. 상대 딜러·힐러 항은 모두 1배입니다.

총점은 다음과 같이 계산합니다.

```text
총점 = 상성 가중치 × Σ(상대 5명 상성 × 상대 역할 가중치)
     + 궁합 가중치 × 아군 궁합 합계
     + 맵 가중치   × 해당 영웅의 전장 점수
```

`BLOCK_WEIGHT` 기본값은 상성 1.0, 궁합 0.0, 맵 0.6입니다. 궁합은 데이터가 없어 합계도 0이며 설정은 비활성입니다. 전장 미선택·맵 관계 누락도 맵 항을 0으로 계산합니다. 예를 들어 상성 합계 5점인 위도우메이커는 하바나(+3)에서 `5 + 0.6×3 = 6.8점`입니다.

첨부 맵 점수는 픽률에서 영웅별 기본 인기도와 전장 전체의 효과를 제거한 값을 −3~+3으로 변환한 자료입니다. 앱에서는 제공된 값을 그대로 읽습니다. 맵 점수는 승률을 뜻하지 않습니다.

등급은 `grade_cuts.json`의 역할별 고정 경계선을 읽어 만듭니다. 총점이 `cuts[i]` 이하이면 `labels[i]`, 모든 경계선을 초과하면 마지막 라벨입니다. 등급을 크게, 원래 점수를 작게 함께 표시합니다. 추천 조합 안에서의 순위·백분위는 등급에 영향을 주지 않으므로, 1위 영웅도 불리한 등급일 수 있습니다. 가중치를 조절해도 경계선은 고정이며, 튜닝 완료 후 별도로 재산출해야 합니다. 파일의 `block_weight`·`enemy_weight`는 코드의 **기본값**과 일치하는지 테스트합니다.

슬라이더 범위는 상성·맵 0~2(0.05 단위), 역할별 상대 탱커 가중치 0~5(0.5 단위)입니다. 선택한 맵과 가중치는 합산 전에 적용하며, 총점은 화면 표시용 두 자리로 반올림해서 정렬하지 않습니다. 소수 곱셈의 미세한 계산 오차만 12자리에서 정리해 수학적으로 같은 점수를 동점으로 유지합니다.

영웅 ID는 내부 식별자이므로 공식 URL과 같을 필요가 없습니다. `freya` → 공식 `freja`, `sion` → 공식 `shion` 등은 초상화 다운로드 단계에서 대응합니다. 기존 JSON·CSV 연결은 유지했습니다.

## 확인과 배포 파일 생성

```sh
npm test
npm run grades:check
npm run build
npm run portable
```

`dist/`에는 웹 배포용 파일이, `release/OW_Coach.html`에는 초상화와 전장 썸네일을 내장한 더블클릭 실행용 단일 파일이 생성됩니다. 점수나 코드를 바꾸면 다시 생성해야 합니다. 테스트는 명시적인 과거 데이터·가중치로 v0.3~v0.5 회귀를 보존하고, v1.5 손계산·설정 전환·CSV 검증과 맵 합산·가중치, 데이터 53×30의 완전성, 설정 저장·복원, 고정 등급 경계, 선택 사항인 선호 필터, 가능 포함 추천, 전체 후보 추가 제안 조건·경계·빈 선택을 확인합니다. 실제 데이터를 갱신할 때에는 `STATE.md`의 회귀 기준도 함께 검토하세요.

## 나중에 맵 점수를 갱신할 때

1. 새 `map_scores.json`을 `data/build/map_scores.json`에 덮어씁니다. 구조는 `{영웅id: {전장id: 점수}}`이며 소수를 허용합니다. 같은 ID를 유지하면 화면 코드를 고칠 필요가 없습니다.
2. `npm run grades:calibrate`로 현재 데이터·가중치에 맞는 등급 경계를 다시 만듭니다. `npm run grades:check`로 재현성을 확인합니다.
3. `npm test`와 `npm run build`를 실행합니다. 점수 변경으로 실제 데이터 손계산 예제가 달라졌다면 원본 값을 다시 계산해 기대값을 검토합니다. 맵 미선택 v0.5 기준 자료는 맵 점수 변경 때문에 바꾸지 않습니다.
4. 오프라인 파일도 쓰려면 `npm run portable`로 다시 만듭니다. 전장 ID나 목록이 바뀐 경우에만 `maps.json`과 같은 이름의 썸네일까지 함께 갱신합니다.

v1.5에서는 과거 기본 가중치를 자동 전환하며, 직접 조정한 사용자 설정은 보존합니다. 새 기본 데이터 확인 시 **개발용 설정 → 기본값으로**를 눌러 비교하세요.

## GitHub Pages

1. 프로젝트 내용을 GitHub 저장소의 `main` 브랜치에 올립니다. `node_modules`, `dist`, `release`는 제외합니다.
2. Settings → Pages → Source에서 GitHub Actions를 선택합니다.
3. 이후 `main`에 변경을 올리면 포함된 `.github/workflows/deploy.yml`이 검사·빌드·배포합니다.

v0.5는 [PR #2](https://github.com/godmooner/ow-coach/pull/2)로 병합되었고, v1.0도 `main`의 `0869b1d`에 반영되었습니다. v1.0.1은 PR #3으로 병합되었습니다. 이번 v1.5 패치의 검증·반영 상태는 `STATE.md`를 참고하세요. 파일 경로는 저장소 하위 경로에도 맞게 상대 경로로 처리합니다. [Vite 배포 안내](https://vite.dev/guide/static-deploy#github-pages)

상성 데이터는 제공된 나무위키 추출 자료이며, 초상화는 [오버워치 공식 영웅 페이지](https://overwatch.blizzard.com/en-us/heroes/)에서 확보했습니다. 비공식 팬 도구이며 영웅 이미지 권리는 Blizzard Entertainment에 있습니다.
