# v1.5 데이터·가중치 패치

기준: v1.0.1 (`main` 13b1b50). 제공된 영웅 53명·전장 30개의 자료와 앞서 수행한 영상/영웅 문서 학습 및 사례 검증을 반영했다. 최신 라이브 패치를 새로 수집한 데이터는 아니다.

## 무엇을 반영했나

영상 학습에서 반복된 핵심은 영웅의 가치가 결투 승패뿐 아니라 사거리, 접근 경로, 고지대, 진입·이탈, 팀의 보호와 압박 조건에 따라 달라진다는 점이었다. v1.5는 이 관점을 기존 추천기에 부분적으로 반영한다.

1. 기존 영웅 문서가 대인전과 팀파이트를 명시적으로 구분한 관계 18개는 평균값 대신 팀전 값을 채택했다. 상세 수치·원문 평가·파일·줄·해시는 `data/revisions/v1.5-matchup-corrections.json`에 있다. 영상에서 직접 18개 수치를 얻었다는 뜻은 아니다.
2. 상대 탱커 하나가 전체 추천을 지나치게 좌우하지 않도록 탱커 가중치를 낮췄다.
3. 맵의 사거리·접근성 차이가 추천에 더 반영되도록 맵 가중치를 0.3에서 0.6으로 올렸다. 검토 사례에서 0.9로 올리는 것만으로는 상대 리퍼·바스티온의 진입 저지보다 고지대 가점이 과해질 수 있어 0.6을 선택했다.
4. 바뀐 점수 분포에서 역할별 등급 경계를 다시 만들었다.

로드호그 전체 감점이나 반대 방향 상성의 자동 반전은 하지 않았다. 하나의 영웅 쌍이 정반대 값이어야 한다는 제약도 없다. 18개는 팀전용 기본 평가이며, 아군 지원이 충분해야 성립하는 등의 조건까지 모두 해결한 수치는 아니다.

## 데이터와 공식

- 영웅 상성: 53×53. 비미러 기록 2,754개, 미러 53개는 계산상 0. 자료가 없는 도미나→캐서디·캐서디→도미나 2개는 JSON에 없고 계산상 0이다. Excel에는 빈칸으로 구분한다.
- 맵 상성: 53×30=1,590개. 수치 변경 없음. 제공된 픽률에서 영웅의 기본 인기도와 전장 전체 효과를 제거한 선호 점수이며 승률이 아니다. 전장 구간별 차이는 포함하지 않는다.
- CSV도 전체 53명으로 동기화했다. 이전 딜러 전용 CSV로 전체 JSON을 덮어쓰는 실수를 변환기가 거부한다.

```text
총점 = Σ(상대 5명에 대한 상성 × 상대 역할 가중치) + 0.6 × 맵 원점수
```

| 내 역할 | 상대 탱커 | 상대 딜러 | 상대 힐러 |
|---|---:|---:|---:|
| 탱커 | 2 | 1 | 1 |
| 딜러 | 1.5 | 1 | 1 |
| 힐러 | 1.5 | 1 | 1 |

상성 영역 가중치 1, 맵 0.6, 아군 궁합 0. 맵 미선택이면 맵 항은 0. 모스트 순위 가산점, 새로운 조합 분류기, 아군 입력은 추가하지 않았다. 역할 제한과 동점 처리는 유지한다. 선호 설정·추천 표시 규칙은 아래와 같이 함께 갱신했다.

## 함께 반영한 선호 영웅 업데이트

- 역할 선택 직후 상대·전장 화면으로 이동한다. 선호 미설정은 해당 역할 전체 영웅에서 최대 3명을 추천한다.
- `선호 영웅(모스트) 선택` 버튼으로 별도 화면에 들어가 역할별 모스트·가능을 저장한다. 완료하면 원래 역할·상대·전장을 유지한 채 돌아온다.
- 모스트 1~3순위와 가능을 합쳐 점수순 최대 3명을 추천한다. 후보가 총 1~2명이면 해당 인원만 표시한다. 개인 순위는 표시용이며 가산점이 없다.
- 선호 추천이 모두 약간 불리 이하이면 같은 역할 전체 최고 영웅을 1명 추가 제안한다. 이미 주 추천에 나온 전체 최고는 중복 표시하지 않는다. 선호를 비우면 전체 후보 추천으로 돌아간다.
- 이번 UI 변경은 데이터·가중치·등급 경계를 다시 바꾸지 않는다.

## 고정 등급 경계

각 열의 상한 이하이면 해당 등급이다. 마지막 경계를 넘으면 매우 유리다.

| 등급 | 탱커 상한 | 딜러 상한 | 힐러 상한 |
|---|---:|---:|---:|
| 매우 불리 | -8.40 | -7.76 | -8.42 |
| 불리 | -4.22 | -3.62 | -4.88 |
| 약간 불리 | -1.08 | -0.52 | -2.12 |
| 중립 | 1.62 | 2.10 | 0.36 |
| 약간 유리 | 4.72 | 5.12 | 3.14 |
| 유리 | 8.82 | 8.96 | 6.58 |

시드 20260921, xorshift32로 상대 1탱·2딜·2힐 조합 30,000개를 생성했다. 같은 역할 안의 중복 픽은 없다. 각 영웅은 역할 내 균등 추출, 맵은 30개를 순환해 각각 1,000번 사용한다. 매 조합마다 역할별 전체 후보를 계산해 탱커 45만·딜러 72만·힐러 42만, 총 159만 점수를 모았다. 모스트 필터는 이 분포에 영향을 주지 않는다.

5/20/40/60/80/95 백분위의 nearest-rank 값을 소수 둘째 자리로 반올림한 고정 경계다. 등급별 목표 비율은 약 5/15/20/20/20/15/5%이며 실제 비율은 등급 JSON에 기록했다. 각 경기 조합 안의 순위를 등급으로 바꾸지 않는다. 맵 미선택도 같은 경계를 사용한다.

이 등급은 여러 가상 상황에서의 점수 위치이며 실제 승리 확률이나 동일 실력에서의 승률 추정치가 아니다. 실제 픽률 분포로 가중 학습한 결과도 아니다. 역할마다 다른 경계이므로 서로 다른 역할의 등급으로 팀 총강도를 비교하지 않는다.

## 대표 대조 사례

| 전장 | 상대 | 탱커 추천 상위 |
|---|---|---|
| 서킷 로얄 | 시그마·위도우메이커·애쉬·젠야타·일리아리 | 시그마 9.80 / 레킹볼 9.46 / 윈스턴 8.76 |
| 감시 기지: 지브롤터 | 자리야·리퍼·바스티온·아나·젠야타 | 시그마 9.26 / 윈스턴 1.80 |

두 번째 시그마 손계산: `2×2 + 0.5 + 1 + 2 + 2 + (-0.4)×0.6 = 9.26`.
이 사례들은 이전 검토에서 선택한 실용적인 회귀 기준이며 모든 조합의 정확성을 입증하지는 않는다.

## 저장 설정과 업데이트

기존 `ow-coach.weights.v1` 값이 옛 기본값이면 v1.5 기본값으로 자동 전환한다. 실제 사용자 설정은 보존한다. 새 `ow-coach.weights.v1.5` 키에 저장한 뒤에는 사용자가 일부러 옛 값을 선택해도 다시 자동 전환하지 않는다. 모스트 저장 키·내용은 바꾸지 않는다. 손상되거나 사용할 수 없는 저장소는 안전하게 기본값을 쓴다.

데이터 수정 시:

```sh
# CSV로 수정한 경우만 먼저 실행; JSON 직접 수정과 동시에 하지 않는다.
npm run data:from-csv
npm run grades:calibrate
npm test
npm run grades:check
npm run build
npm run portable
```

`grades:check`는 현재 JSON 4개의 해시, 가중치, 고정 시드로 다시 계산한 결과 전체를 확인한다. 가중치 슬라이더를 임의로 조정해도 런타임에서 등급은 자동 보정하지 않는다. 그 경우 기본값으로 복원하거나, 정식 기본 가중치를 수정한 뒤 경계를 재산출해야 한다.

Excel은 전달 시점의 전체 데이터와 18개 수정 내역·가중치·등급을 담은 검토/편집 자료다. Excel만 수정해 앱에 자동 반영하는 기능은 없다. 기존 `data/raw`와 원문 파서는 역사 자료이며 v1.5 생성 경로로 쓰지 않는다.
