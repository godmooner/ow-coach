# OW Coach 실행 계획 v0.3 — 데이터 인수인계 반영

v0.2의 1번·3번 작업을 합쳐 딜러 24명 전체를 사용하는 화면을 구현한다. 데이터 확대는 완료되었으므로 3명 표본과 수집 작업을 반복하지 않는다.

## 확정 규칙

| 원문 표기 | 점수 |
|---|---:|
| 매우 유리 | +3 |
| 유리 | +2 |
| 약간 유리 | +1 |
| 중립 | 0 |
| 약간 불리 | −1 |
| 불리 | −2 |
| 매우 불리 | −3 |
| 유동적 | 0 |

조건부 등급은 인수인계 데이터의 단순 평균을 사용한다. 타입은 number이며 정수 제한이나 정수 반올림을 하지 않는다. 상대 5명의 점수를 가중치 없이 합산한다. 가능한 합계 범위는 −15부터 +15까지다.

없는 관계와 같은 영웅 관계는 계산 시 0점이다. 누락으로 후보를 제외하지 않는다. 화면 안내는 ‘미입력 상성은 0점으로 계산’ 한 줄을 유지한다. 동점이면 영웅 목록 순서로 상위 3명을 표시한다.

## 데이터와 화면

- 영웅 53명: 탱커 15·딜러 24·힐러 14.
- 상성 1,190행, 소수 점수 28행, 미기재 58쌍. 이는 인수인계 당시 수치이며 향후 업데이트를 제한하는 고정값이 아니다.
- 앱은 data/build/heroes.json과 data/build/matchups.json을 직접 읽는다. 별도 복사본이나 형식 변환이 필요 없다.
- matchups.json은 {딜러id: {상대id: 점수}} 구조 그대로 유지한다.
- 상대 1/2/2 선택, 선택 취소, 초기화, 상위 3명과 총점만 구현한다.
- 영웅 ID와 공식 URL은 초상화 출처 매핑으로 연결한다. ID를 바꾸려면 양쪽 상성 키와 영웅 목록도 함께 바꿔야 한다.

## 이어서 진행할 순서

1. 전체 데이터로 선택·추천 화면을 완성한다.
2. 소수 합산, 미입력, 동점, 선택 제한을 확인한다.
3. 사용자가 직접 실행해 보고 불편한 점 하나를 고친다.
4. GitHub 저장소에 연결하고 Pages 배포를 진행한다.

한 작업자만 코드를 수정하고 종료 시 STATE.md를 갱신한다. 가중치 연구, 메타 분석, 모든 변경의 교차 검토는 이번 범위에 추가하지 않는다.

다음 작업자에게 전달할 지시문:

> README.md와 STATE.md를 읽고 요청한 변경 하나를 구현해줘. 점수는 +3/+2/+1/0/-1/-2/-3이며 소수도 그대로 합산해. 유동적·미입력·미러 관계는 0점으로 처리하고 누락 때문에 추천 후보를 제외하지 마. 데이터는 data/build의 JSON을 직접 사용해. 기존 화면과 계산을 확인한 뒤 STATE.md에 변경과 다음 작업을 남겨줘. 3명 표본이나 데이터 수집 단계로 되돌아가지 마.
