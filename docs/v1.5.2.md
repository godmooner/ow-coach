## 계산과 표시

`recommend.ts`의 `scoreHero()`는 기존 점수 계산을 공유한다. 상대 항에는 내 역할별 상대 역할 가중치와 상성 영역 가중치를 모두 곱한다. 전장 항에는 맵 영역 가중치를 곱한다. 아군 궁합은 기존처럼 미연결이므로 0점이다. 조합 선택만으로 아군 점수를 생성하지 않는다.
총점은 기존 `combineScoreBlocks()` 규칙대로 계산한다. 반환되는 추천 목록 구조, 후보·정렬·동점·고정 등급·모스트 규칙은 바꾸지 않는다. `App.tsx`가 같은 입력과 설정으로 상세 기여도를 가져와 `RecommendationCard`에 전달한다.

예: 상대 원합계 7.5×0.65=4.875, 전장 원점수 -1.37×0.35=-0.4795, 아군 0. 실제 총점 4.3955를 화면에서 4.40으로 표시한다. 내역은 전장 -0.48 + 상대 4.88 + 아군 0 = 4.40이다.
`scoreBreakdown.ts`는 정수 센트 단위로 표시값을 맞춘다. 전장·아군을 소수점 둘째 자리로 반올림하고, 상대 표시값은 표시 총점에서 두 항을 뺀 값으로 정한다. 그래서 개별 반올림으로 합계가 0.01점 어긋날 때도 화면 합계가 일치한다. 상대 표시값은 단독 반올림 결과와 0.01점 차이날 수 있다. 계산·정렬용 값에는 이 보정을 적용하지 않는다.
표시상 0인 아주 작은 값은 +0/−0 대신 0으로 표시한다.

## 검증과 후속 작업

- `npm test`: 기존 71개 + 새 3개 = 74개 통과. 가중치 적용 후 기여도·미입력/미러 0점·양수와 음수의 반올림 합계 검사.
- `npm run build`, `npm run portable` 통과.
- 변경 전후 52,576개 추천 결과를 대조했다. 16개 상대 구성, 전장 미선택+30개 전장, 세 역할, 기본·사용자 가중치에서 결과 JSON 해시가 동일하다.
- 실제 브라우저에서 PC·모바일 사진 크기, 점수 합계, 아군 선택 전후 유지, 슬라이더 변경, 전장 해제를 확인했다. 1440·390·320px 화면에서 가로 넘침과 JavaScript 오류가 없었다.

배포 단계에서 개발 표시를 제거할 때는 `RecommendationCard.tsx`의 `.score-breakdown` 영역과 관련 CSS를 제거한다. 표시 함수를 쓰지 않으면 `scoreBreakdown.ts`도 제거할 수 있다. 데이터와 기존 점수 계산은 손대지 않는다. 아군 궁합 데이터 연결은 별도 작업이다.
