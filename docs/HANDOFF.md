## ⚠ v0.2에서 바뀐 것 — 반영 필수

### 1. 점수 스케일이 ±2 5단계가 아니라 ±3 7단계다

원본 나무위키에 `약간 유리` / `약간 불리`가 실재해서 5단계로는 표현이 안 된다.

| 표기 | 점수 |
|---|---:|
| 매우 유리 | +3 |
| 유리 | +2 |
| 약간 유리 | +1 |
| 중립 | 0 |
| 약간 불리 | −1 |
| 불리 | −2 |
| 매우 불리 | −3 |

**v0.2 §7 끝의 지시문에 `+2/+1/0/-1/-2`가 남아 있다면 위 표로 고칠 것.**

### 2. 점수에 소수가 있다 (1190행 중 28행)

원문이 조건부로 두 등급을 적은 경우(`매우 불리 (대인전) 유리 (팀파이트)`)가 있어서, **조건을 무시하고 단순 평균**했다. 그래서 ±0.5, ±1.5, −2.5 같은 값이 나온다.

**점수를 정수로 가정한 타입이나 검증을 넣지 말 것.** `number`로 받으면 된다. 합산 로직은 그대로 동작한다.

### 3. `유동적`이라는 8번째 표기가 있다

원문 표현이고 "상황에 따라 다름"이라는 뜻이다. **0점으로 처리**했다. 등급이 `유동적` 하나뿐인 행이 12건 있고 전부 0점이다.

### 4. 데이터가 완전하지 않다 — 58쌍이 원문에 아예 없다

나무위키 문서가 신규 영웅을 아직 반영하지 않아서다 (D.Mon 16건, 시온 12건, 시에라 11건 등).

`matchups.json`에 **키 자체가 없다.** v0.2 §1대로 조회 실패 시 0점 처리하면 된다. 없는 영웅이라고 추천에서 빼지 말 것.

### 5. `heroes.json`이 이미 만들어져 있다

v0.2 §4의 1번 묶음에 들어 있던 작업이다. 53명 전원 id/한글명/역할/초상화 경로가 들어 있으니 그대로 쓰면 된다.

## 넘기는 파일

| 파일 | 내용 |
|---|---|
| `heroes.json` | 53명. `{id, name_ko, role, portrait}`. role은 `tank`/`damage`/`support` |
| `matchups.json` | **앱에 바로 넣을 것.** `{ 딜러id: { 상대id: 점수 } }` |
| `matchups.csv` | 사람이 읽고 고치는 용. 6컬럼 |
| `ow_dealer_matchups.xlsx` | 위 CSV + 특이사항/평균적용/원문누락 시트 |
| `review.md` | 특이사항 12건 |
| `scripts/parse_matchup.py` | 원문 txt → 데이터. 모델 호출 0회 |
| `scripts/build_xlsx.py` | 데이터 → 엑셀 |
| `data/raw/*.txt` | 나무위키 원문 24개 (재현용) |

`matchups.json` 형태:
```json
{ "genji": { "ana": 0, "ashe": 3, "bastion": 3, "domina": -0.5, ... } }
```

부호 방향: **딜러(키)가 상대(값의 키)를 만났을 때의 유리(+)·불리(−)**.

## 검토해줬으면 하는 것

1. `matchups.json` 구조가 `recommend.ts`에 바로 들어가나? 다른 형태가 편하면 말해줘 — 변환은 스크립트 재실행이라 비용이 거의 없다.
2. 소수 점수 때문에 깨지는 부분이 있나?
3. 원문 누락 58쌍을 0점으로 처리할 때 UI에 표시가 필요한가? (v0.2는 "미입력 상성은 0점으로 계산" 한 줄만 표시하기로 했다)
4. `heroes.json`의 영문 id가 실제 영문명과 다를 수 있다. 신규 영웅(안란·엠레·프레야·시온·시에라·벤데타·D.Mon·도미나·미즈키·우양·제트팩 캣)은 로마자를 추정했다. 초상화 파일명과 맞추려면 지금 고치는 게 낫다.
